📘 CeyPOS Database Structure & MCP API Endpoint Specification
1. Comprehensive Database Schema
Each shop in CeyPOS gets its own SQLite database, named by shop_id (e.g., shop_1001.sqlite). This enables isolation, portability, and scalable AI analytics.
Tables:
Table: shop_meta 
- shop_id INTEGER PRIMARY KEY
- shop_name TEXT
- owner_email TEXT
- location TEXT
- created_at DATETIME
Table: inventory
- item_id INTEGER PRIMARY KEY AUTOINCREMENT
- inventory_code TEXT UNIQUE
- barcode_id TEXT UNIQUE
- name TEXT NOT NULL
- category TEXT
- sku TEXT UNIQUE
- price DECIMAL(10,2)
- stock INTEGER DEFAULT 0
- stock_last_month INTEGER DEFAULT 0
- restock_suggestion INTEGER DEFAULT 0
- created_at DATETIME
- updated_at DATETIME
Table: customers
- customer_id INTEGER PRIMARY KEY AUTOINCREMENT
- name TEXT
- email TEXT
- phone TEXT
- total_spent DECIMAL(10,2) DEFAULT 0
- visit_count INTEGER DEFAULT 0
- last_visit DATETIME
- created_at DATETIME
Table: transactions
- transaction_id INTEGER PRIMARY KEY AUTOINCREMENT
- receipt_id TEXT UNIQUE
- transaction_code TEXT UNIQUE
- customer_id INTEGER
- subtotal DECIMAL(10,2)
- discount DECIMAL(10,2)
- tax DECIMAL(10,2)
- total DECIMAL(10,2)
- payment_method TEXT
- created_at DATETIME
Table: transaction_items
- id INTEGER PRIMARY KEY AUTOINCREMENT
- transaction_id INTEGER
- item_id INTEGER
- inventory_code TEXT
- quantity INTEGER
- unit_price DECIMAL(10,2)
- subtotal DECIMAL(10,2)
Table: daily_sales
- date TEXT
- total_sales DECIMAL(10,2)
- transactions_count INTEGER
- top_item TEXT
Table: inventory_forecast
- item_id INTEGER PRIMARY KEY
- item_name TEXT
- avg_daily_sales INTEGER
- recommended_stock INTEGER
- suggested_restock_date TEXT
2.Endpoints (with Purpose)
/query — POST - Accepts natural language prompt and db_path. Returns SQL + executed results + answer.
/schema — GET - Returns schema for a given shop SQLite DB.
/sample — GET - Returns sample rows for AI prompt context.
/sql — POST - Accepts raw SQL + db_path. Executes and returns result.
/summarize — POST - Accepts executed SQL + results + original prompt. Returns natural language summary.
/analytics/daily — GET - Returns chart-ready daily sales data.
/inventory/add — POST - Adds new inventory row from mobile/barcode scan.
/cart/add — POST - Adds item to cart from barcode scan session.
/transaction/checkout — POST - Finalizes checkout, writes to transactions and transaction_items.
/inventory/upload — POST - Accepts Excel upload, validates, inserts to inventory.
/shop/register — POST - Registers new shop, creates shop_meta row, initializes SQLite DB.
/settings/update — POST - Updates shop settings like logo, name, billing preferences.

**Mobile Session Endpoints**:
/mobile/session/create — POST - Creates new mobile session with QR data.
/mobile/session/validate — POST - Validates QR session and establishes WebSocket.
/mobile/barcode/scan — POST - Processes barcode scan from mobile device.
/mobile/inventory/sync — POST - Syncs mobile inventory changes to desktop.
/mobile/cart/sync — POST - Syncs mobile cart data with desktop POS.
/mobile/checkout/process — POST - Processes mobile checkout and syncs transaction.

3. Notes on State & Flow

All endpoints are state-aware, isolated per shop via SQLite. The MCP server dynamically loads the correct database via shop_id. Frontend and mobile apps interact via RESTful endpoints, WebSockets for cart/session sync, and AI-enhanced query capabilities.

4. Security Recommendations

- Use session or token auth to verify access.

- Always sanitize SQL generated by AI.

- Only allow modifying queries from authenticated admins.

- Log all SQL queries and AI prompts for audit.
